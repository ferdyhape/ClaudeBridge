API Documentation

One base URL, no separate host. Get a key on the Account page, then call anything below. Examples use .

Authentication

Send it as Authorization: Bearer <key>. A key maps to one Claude account, and every request with it runs isolated under that account. Invalid or revoked keys get a 401.

Example header 
Authorization: Bearer csk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Talking to Claude

POST /ask

One prompt in, one answer out. Text only — no tool or file access on Claude's side. Paste raw data (JSON, logs, whatever) straight into prompt and ask it to work with that.

Body
  • prompt (string, required) — your question, instruction, or data.
  • sessionId (string, optional) — session_id from a previous response, to continue that conversation.
  • model (string, optional) — haiku, sonnet, opus, or a full model name. Defaults to the account's model.
  • systemPrompt (string, optional) — swap the default persona for this request.
Request — data analysis
curl -X POST {{ORIGIN}}/ask \
  -H "Authorization: Bearer csk_xxxx..." \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Give a short analysis: {\"cpu\": 92, \"mem\": 81, \"disk\": 45}"}'
Response 200
{
  "result": "## System Data Analysis\n\nCPU 92% — critical, needs attention...",
  "session_id": "a8157afe-ad41-4273-aaa5-c0d442136ad7",
  "total_cost_usd": 0.0022,
  "usage": { "input_tokens": 212, "output_tokens": 69 }
}
Request — pick a model + override persona
curl -X POST {{ORIGIN}}/ask \
  -H "Authorization: Bearer csk_xxxx..." \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": "Reply with one word: ready",
    "model": "haiku",
    "systemPrompt": "You are a terse status-check responder."
  }'
Response 4xx/5xx
{ "error": "Field 'prompt' (string) is required" }

Account status

GET /auth/status

Login status of the account this API key represents.

Response 200
{
  "loggedIn": true,
  "authMethod": "claude.ai",
  "email": "name@example.com",
  "orgName": "Example Org",
  "subscriptionType": "team"
}
POST /auth/logout

Logs out the Claude account behind this key. The key itself stays valid — log back in on the Account page whenever you want to use it again.

Response 200
{ "ok": true, "output": "Successfully logged out..." }
GET /whoami

The internal session id this API key/cookie represents. Useful for debugging.

Response 200
{ "uid": "b879026b-a18d-4cbd-bbbf-729daa6dbae0" }

Managing API keys

From the Account page, or directly through these — handy for automated key rotation.

GET /auth/api-keys

Lists this account's API keys. The raw key value is never returned again after creation.

Response 200
{
  "rows": [
    {
      "id": "3406ebd1-22f3-41a0-8df0-2b3dd68a52bb",
      "name": "backup-script",
      "key_prefix": "csk_-1AOM2",
      "created_at": "2026-08-27T15:21:36.000Z",
      "last_used_at": "2026-08-27T15:21:48.000Z"
    }
  ]
}
POST /auth/api-keys

Creates a new API key for this account. The key value in the response only appears this once — save it immediately.

Request
{ "name": "backup-script" }
Response 200
{
  "id": "3406ebd1-22f3-41a0-8df0-2b3dd68a52bb",
  "name": "backup-script",
  "key": "csk_-1AOM2lMq8lpZshq_qAJH35Le0vbBysdvi7rdVXdpVY",
  "prefix": "csk_-1AOM2"
}
DELETE /auth/api-keys/:id

Revokes one API key. Effective immediately — the next request with that key is rejected with 401.

Response 200
{ "ok": true }
Response 404
{ "error": "Key not found" }

Available models

GET /auth/models

The real model ids your account can use (e.g. claude-opus-4-5-20251101), fetched live from Anthropic. Any of these work as model on /ask — the short aliases still work too.

Response 200
{
  "models": [
    { "id": "claude-opus-5", "displayName": "Claude Opus 5" },
    { "id": "claude-sonnet-5", "displayName": "Claude Sonnet 5" }
  ]
}
Right now
Log in to see your models here.

Notes

  • New logins happen on the Account page — there's no login endpoint.
  • Requires an active Claude Pro, Max, or Team subscription. Free accounts can't log in here.
  • One account, many keys — create and revoke freely.
  • /auth/models can 502 if the account's token needs a refresh. A successful /ask call fixes that.
